# Original intent

Recorded 2026-10-07 from the founding conversation. This preserves the starting point; [north-star.md](north-star.md) describes the current direction. The synthesis below is a paraphrase, except for the explicitly quoted excerpts.

The [complete founding messages and early feedback](founding-messages.md) are preserved verbatim as source material. This summary supports quick orientation; consult the original wording when interpretation matters.

## The user’s starting point

The user wants a personal life protocol spanning practices, tools, products, exercise, and care for areas such as hair, skin, and nails. Bryan Johnson's protocol illustrates the general idea, not a required set of interventions to copy.

The user already owns and uses products. Some choices are established preferences; others were selected without a particular reason. Simply maintaining a list of possessions or quantities offers limited value because people normally remember their products and can use the physical packaging as a reference.

The main burden is processing recommendations: a short about a “magic” shampoo, a new vitamin, advertisements, and other claims. Investigating evidence, checking relevance, comparing with existing practices, remembering findings, and keeping up with changing science or needs consumes significant time and attention.

The assistant should absorb that burden and help assemble a protocol that makes sense for this user. Practical constraints matter: a slightly better option may not justify its extra cost; a promising product may not be sold locally. Research should account for reality rather than end with an inaccessible recommendation.

> “Like be able to receive the noise: new products, new ads, new whatever, and just try to build something that makes sense for me.”

## The foundation request

The user asked for an actual initialized repository, with assistant rules or workflows, an observable canonical state that the AI can update and the user can understand, and a clear record of the project's intent.

The user also asked that the intent remain adaptable: future work should remember why this exists, while allowing experience to change its direction rather than treating the first iteration as an inflexible specification.
