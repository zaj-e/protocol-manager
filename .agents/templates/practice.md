# Practice-card template

Copy the section below into one category page. Replace placeholders with user-provided information. The template is not a real practice record.

## PXXX: Practice name

- **Purposes:** one or more user goals; distinguish advertised purposes from the user's desired outcomes. Use “not yet provided” when unknown.
- **Practice/product:** what the user does or uses; include formulation or model only when relevant.
- **Last reported status:** active | paused | stopped | unknown.
- **Status confirmed on:** YYYY-MM-DD, or not yet confirmed. This date applies to the status only.
- **Frequency/amount (last reported):** value and report date, or not yet provided. Preserve an older date when only status is reconfirmed.
- **Choice and reason:** strongly preferred | flexible | arbitrary | unknown, with the user's reason if supplied.
- **Report source:** user report/edit and date for the recorded setup; identify separate report dates when details came from different reports.

### Evidence by objective

Add links when this practice has actually been evaluated. For each objective, name the outcome and relevant use context, link the applicable section on its topic page in `research/`, and show that objective's review date. For example, a fictional card might have separate entries for “cleaning” and “reducing irritation”; neither is a verdict on all possible benefits. Omit this section until there is a review. Keep research conclusions, reasoning, and source detail on the topic page.

After a product or regimen change, label retained links **Applicable**, **Needs reassessment**, or **Historical**, with the relevant context and a brief reason. Applicable means the review addresses this setup; its verdict may be favorable, negative, or uncertain. Other links do not establish a conclusion about this setup. Historical links can live with the previous setup in this card's history. Follow the [replacement checks](../workflows/update.md#product-or-regimen-replacement-checks); preserve review dates and the prior setup's facts.

### Observations and meaningful history

Keep short dated observations, motivations, meaningful changes, relevant clinician instructions, explicit start/stop dates, and reported periods of continuous use here when useful. Preserve previous product/regimen context before changing the latest fields. Group history by product or setup within the card; do not create a separate file for every update or duplicate a full snapshot for an unchanged confirmation. Record the actual source/report date and retain material prior details. Missing history is unknown, not evidence of adherence or non-use.

Reported adverse reaction details belong only in `state/reactions.md`. Add a link to the relevant product section here; retain it after stopping or replacing the product, clearly associated with the old setup. Do not copy symptoms into a second canonical history or imply that the reaction applies to the replacement.

Give every practice a unique stable `P` ID across all categories. Keep stopped and paused cards with their history. Use ordinary headings so Markdown viewers provide navigation; add a short local jump list if a category becomes long. Cross-link the canonical card from other categories instead of copying its fields.

A category is navigation, not a restriction on purposes. A tool used in one regimen for several objectives can stay in one card. Distinct uses with different regimens can have separate practice cards referring to the same tool; their evidence conclusions remain scoped to each use. No separate tool registry is required in this iteration.
